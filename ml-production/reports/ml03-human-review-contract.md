# ML-03 真实人工复核与批准记录

只有独立外部数值门槛通过后，才安排两名真实且独立的复核者，逐条检查冻结外部集的至少 40 个适用仓库。生成的 `human_review.csv` 是空白工作表，不是已完成的复核或批准；复核应在副本中填写，保留冻结原件。至少覆盖各个主要簇、中心、边界和不同规模，复核历史事实、窗口和建议的中性簇名称。各人必须独立填写判断和理由；出现不同判断时保留仲裁过程及结论。

供运行时核对的复核 JSON 使用 `items` 数组。每项包含来自外部 `details.json` 的 `repository_id` 和 `cluster_id`，以及 `reviewer_a`、`reviewer_b`、`assessment_a`、`assessment_b`、`reason_a`、`reason_b` 和 `resolution`。两人的判断统一使用 `supports`、`opposes` 或 `uncertain`；理由和结论均须为实际记录。复核仓库必须在正式外部详情中 `in_domain=true`，簇编号必须匹配；每个簇至少有一条两位复核者均支持的记录。以上只是机器可检查的最低完整性条件，不能代替业务判断。

批准记录需包含两位不同复核者、实际复核仓库数、`business_review_passed=true`、`conflicts_resolved=true`、负责人、实际批准时间和各簇中性名称，并引用数值验收、外部详情、复核 JSON 及其各自 SHA-256。`review_agreement_rate` 为两人相同判断条数除以复核条数；运行时会核算该数字，但一致率高不自动等于业务通过。数值验收记录、训练数据和模型哈希、特征版本及注册表适用仓库必须彼此匹配。

模型目录和审批资料只能由获授权人员管理。哈希和字段检查不能证明签署人身份，也不能证实文字意见真实；负责人仍须核验人工身份、意见、仲裁及权限，确认部署环境保护可信目录。当前没有真实复核记录，也没有负责人批准；测试用的合成记录只用于故障与回退测试。

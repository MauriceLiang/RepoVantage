# 前后端契约修复方案

> 状态：待实施
> 基线：已合并的 `main`，提交 `cdccdd4`（2026-10-13）
> 范围：本轮联调中确认的前后端 JSON 契约不匹配；本文是修复说明，不代表代码已修改。

## 1. 结论

本轮确认了 5 类响应数据会被前端 Pydantic DTO 拒绝或无法正确表达的问题。主要原因是后端按当前数据状态返回 `featured`、`null`、`attempt=0` 和小数天数，而前端模型对这些值限制过严。

建议让前端 DTO 和页面显示遵循后端已有语义，并同步修订权威 API 契约文档 `03_API接口契约_v1.0.md`。后端不需要为这些场景伪造时间、把未知值改成零，或提前增加任务尝试次数；本方案不涉及数据库迁移。

## 2. 已确认问题

| 问题 | 后端实际响应 | 前端当前限制 | 影响 |
|---|---|---|---|
| 数据集类型不匹配 | `/api/v1/datasets` 返回 `type="featured"` 的 `featured-default` | `Dataset.type` 只允许 `research`、`library` | `APIClient.datasets()` 整体解析失败，依赖数据集列表的页面无法继续加载 |
| 采集时间允许为空 | 空数据集的 `source_metadata.collected_at` 为 `null` | `SourceMetadata.collected_at` 要求 `datetime` | 新安装或尚未采集的 library/research 总览、研究统计响应无法解析；来源信息格式化也不能接收空值 |
| 缺失率允许为空 | `records_total=0` 时 `/research/data-quality` 返回 `rate: null` | `MissingField.rate` 要求 `float` | 空研究样本的数据质量响应无法解析；分母为零时缺失率本身不可计算 |
| 排队任务尝试次数为零 | 新建任务在首次 Worker claim 前返回 `attempt=0` | `Task.attempt` 限制为 `>=1` | 排队任务列表和详情无法解析 |
| 仓库年龄可为小数 | 分析指标按采集时间计算并四舍五入到一位小数，例如 `2477.6` | `AnalysisMetrics.age_days` 要求 `int` | 已完成的仓库分析响应在年龄为小数时无法解析 |

### 代码证据

- 数据集：后端种子定义见 `../backend/app/services/repositories.py`；后端 schema 已允许 `featured`，见 `../backend/app/schemas/analytics.py`；前端限制见 `../frontend/api/models.py` 的 `Dataset`。
- 空值：后端来源时间见 `../backend/app/services/analytics.py` 的 `_source_metadata`；空样本缺失率见同文件 `get_data_quality`；前端字段见 `../frontend/api/models.py` 的 `SourceMetadata`、`MissingField`。
- 任务计数：数据库默认值见 `../backend/app/persistence/models.py`，Worker 在 claim 时才递增，见 `../backend/app/worker/queue.py`；前端限制见 `../frontend/api/models.py` 的 `Task`。
- 小数天数：计算见 `../backend/app/analytics/metrics.py`，前端整数限制见 `../frontend/api/models.py` 的 `AnalysisMetrics`。
- 页面处理：来源时间格式化见 `../frontend/components/feedback.py`；任务计数展示见 `../frontend/pages/operations.py`；数据质量表格见 `../frontend/pages/research.py`。

## 3. 修复分工

### 前端

在 `../frontend/api/models.py` 中放宽 DTO 到与实际响应一致：

```python
Dataset.type: Literal["research", "library", "featured"]
SourceMetadata.collected_at: datetime | None
MissingField.rate: float | None = Field(ge=0, le=1)
Task.attempt: int = Field(ge=0)
AnalysisMetrics.age_days: float | None
```

`ComparisonMetrics.age_days` 也建议改为 `float | None`，让同一指标在两种响应 DTO 中保持一致；当前比较接口没有返回该字段，因此这是契约对齐项，不是本轮复现的解析失败。

页面处理规则：

- `collected_at is None` 时，来源信息显示“未采集”或“未知”；扩展 `../frontend/components/feedback.py` 的 `_format_datetime` 入参类型，不要生成当前时间。
- `rate is None` 时显示“不可计算”或“未知”，不能显示成 `0%`。空数据质量表格中也应让用户看出这是分母为零。
- `attempt=0` 表示任务仍未被 Worker 领取，保留“尝试次数：0”即可；首次 claim 后应为 1，重试继续按实际次数展示。
- `age_days` 接受一位小数；保留现有 `display_value` 的空值展示行为，不把缺失年龄显示为 0。
- `featured` 数据集可由列表接口正常解析；研究统计入口仍按 `research` 类型筛选，不应把精选集当成研究样本。

### 后端

保持当前值语义，并将它们作为接口契约明确下来：

- 数据集类型包含 `research`、`library`、`featured`。
- 尚无采集记录时 `collected_at` 为 `null`。
- 数据集成员数为零时 `missing_fields[].rate` 为 `null`。
- Worker 尚未领取任务时 `attempt` 为 `0`；领取时递增。
- `age_days` 是可含一位小数的数值，缺少创建时间或遇到未来时间时仍为 `null`。

不要通过将空值改成时间、将缺失率改成 `0`、将入队任务预置成 `attempt=1` 或截断 `age_days` 来绕过前端解析。以上会改变数据含义，其中提前增加 `attempt` 还会影响 Worker 的最大尝试次数判断。

### API 契约文档

修复实现时同步更新 `03_API接口契约_v1.0.md`，至少覆盖：

1. `Dataset.type` 的三个合法值，并在 `/datasets` 示例中体现 `featured`。
2. `SourceMetadata.collected_at` 可空，以及无采集数据的示例。
3. 当总成员数为零时 `MissingField.rate` 为 `null`。
4. 排队任务可以 `attempt=0`，运行中的任务可以为 1 或更大。
5. `age_days` 使用数值类型而不是整数类型，示例包含小数和 `null`。

1. 更新前端 DTO 和空值展示。
2. 增加 DTO 回归用例，直接验证后端真实响应形状能被 `APIClient` 对应方法解析。
3. 修订 API 契约示例和字段说明，确保 API 文档、后端响应、前端 DTO 一致。
4. 执行下节验收，并记录真实 UI 是否已验证。

不需要修改数据库 schema 或新增 Alembic migration。

## 5. 验收标准

| 场景 | 验收结果 |
|---|---|
| 空库调用数据集列表 | 含 `featured-default` 的响应可被前端解析；research 筛选行为正确 |
| 空库调用 library/research 总览及研究统计 | `source_metadata.collected_at=null` 可正常解析，页面显示“未采集”或“未知” |
| 空研究样本调用数据质量接口 | 每个 `rate=null` 可解析并显示为“不可计算”或“未知”，不显示 `0%` |
| 读取刚入队任务的列表和详情 | `attempt=0` 可解析并正确显示；Worker claim 后的 `attempt=1`、重试次数仍正常 |
| 读取已完成基础分析 | `age_days=2477.6` 一类小数可解析并显示；`age_days=null` 仍显示未知 |
| API 契约 | 文档字段类型、可空规则和响应示例与实现相符 |

建议回归测试覆盖 `APIClient.datasets()`、library/research overview、research statistics、research data quality、task list/detail 和 repository analysis。测试应同时保留非空正常值的断言，防止放宽 DTO 时误伤原有校验。

## 6. 本轮验证边界

本轮合并后验证已通过后端 pytest（20 项）、临时 SQLite 的 `alembic upgrade head`、数据完整性检查、86 个 Python 文件 AST 解析，以及 26 条前后端 happy-path 联调断言；另复现了 8 个 DTO 拒绝场景，覆盖本文所列契约问题。`pytest` 输出包含一条 Starlette 的 `httpx` 集成弃用警告。

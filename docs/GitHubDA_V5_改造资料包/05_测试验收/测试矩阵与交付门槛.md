# GitHubDA V5：测试矩阵、截图基线与交付门槛

## 0. 验收基线与检查环境

- V4：`07_V4原型资料/V4_可交互单文件.html`、`07_V4原型资料/预览/`。
- V5：开发者需要新增 Vue 源代码、组件测试、Playwright E2E 测试、各屏截图及差异审查。
- 浏览器：Chrome/Chromium 为主，Safari/macOS 做人工关键路径检查。
- 视口：`390×844`、`768×900`、`1280×800`、`1440×900`，必要时按真实内容高度增加截图。
- 验收数据：固定 Mock 数据与固定默认时间；尽量关闭不影响语义的动画以获得稳定对比。

- [ ] T03 已存在仓库重复分析直接进入详情，无重复成员与任务。
- [ ] T04 双击“开始分析”最多生成一个 Mock 任务。

- [ ] T06 仓库页 Tab 切换，“我的仓库”和“发现仓库”状态互不覆盖。

- [ ] T08 勾选 2–5 个已采集仓库，跨筛选/分页仍保留选择。

- [ ] T11 仓库刷新和深度分析任务在任务中心与详情同时可见。
- [ ] T12 移除仓库必须确认，取消后数据不变；历史任务保留。

- [ ] T14 研究数据集切换后统计/质量/导出状态对应新数据集。

## 3. 应用自动化检查建议

Playwright 用例应该验证：

```ts
// 仅展示设计思路，选择器应由 Vue 实现中的稳定 data-testid 确定
await page.goto('/')
await page.getByRole('textbox', { name: /仓库地址/ }).fill('psf/requests')
await page.getByRole('button', { name: '开始分析' }).click()
await expect(page).toHaveURL(/repositories\/\d+/)
await expect(page.getByText(/排队中|采集中|已完成/)).toBeVisible()
```

Mock 场景建议通过 `?scenario=...` 或可控测试 Provider 注入，不要在 E2E 代码中靠随机概率触发失败。截图测试关闭不可控动画并固定日期。

## 4. 缺陷分级

- **P0**：任一导航不可用、分析流程断裂、真实凭据泄露、数据误报、按钮被遮挡、编译失败。
- **P1**：视觉与 V4 明显不一致、列表/弹窗难操作、任务轮询不终止、小屏交互难用、CSV/对比异常。
- **P2**：非关键动画和细节、个别弱说明文案、超小屏轻微间距。

阶段 I：P0/P1 必须全部解决；阶段 II：新增安全/真实数据 P0/P1 必须解决。不允许以“只是 Mock 原型”为由跳过可操作性要求。

## 5. 验收报告必须包含

- 实际 Git Commit SHA、Node/package manager/锁文件版本、运行命令。
- 页面截图路径、对应视口与验收截图差异说明。
- 单测数量与结果、端到端测试数量与结果。
- T01–T30 每项状态（通过/失败/未到阶段），不能笼统写“测试通过”。
- Mock 模式和真实模式分别列明，不能把 Mock 跑通说成真实联调成功。
- 已知局限、回滚办法、后续改进建议。

# GitHubDA 文案与排版规范（V4）

> 适用于 GitHubDA 的交互原型与后续 Vue 实现。目标是**真实工具界面**，而非宣传页、设计展示页或 AI 常见模板。

## 一、表达原则

1. **以任务命名**：标题使用“分析 GitHub 仓库”“仓库”“研究”“任务”“仓库对比”等用户能马上理解的名称。不用“用数据读懂未来”等宣传式口号。
2. **中文优先**：不设装饰性英文眉题、副标题。仅在 GitHub、Stars、Forks、Issues、PR、仓库名、技术语言等必要时保留英文术语。
3. **一句话说明实际功能**：页面标题下面如有说明，限制为一句自然中文；如果标题足够明确，可以不写说明。避免“这一切都在这里”“从数据里寻找规律”等空泛修辞。
4. **不得强制断行制造造型**：中文 H1 不插入 `<br>`，由容器宽度决定换行；避免单字独占一行。英文名、仓库路径按正常分词截断。
5. **一个界面只强调一个主要操作**：如总览中的“开始分析”；列表里的次级操作降低视觉权重。
6. **可核实的数据说明与产品内容分离**：演示提示集中放在界面右上角的“演示数据”，不要在每个区块重复展示“Mock/示例”广告牌。
7. **不要制造没有数据依据的评价**：任务阶段进度不代表数据覆盖率，少量样本不硬画分布图。缺失指标用“—”或清楚的状态说明。

## 二、文字使用规则

| 层级 | 建议尺寸（桌面） | 字重 | 用法 |
|---|---:|---:|---|
| 总览主标题 | 36–40px | 690 | “分析 GitHub 仓库”，避免夸张标语 |
| 业务页标题 | 28–30px | 690 | 仓库 / 研究 / 任务 |
| 内容分区标题 | 17–19px | 650–680 | 最近仓库、最近任务、主要统计 |
| 常规内容 | 13–14px | 400–500 | 描述、输入、表格 |
| 数据数值 | 26–28px | 650–700 | 数量统计，统一数字字体规则 |
| 次要说明 | 12–13px | 400–500 | 时间、范围、少量必要提示 |

中文字距应接近正常，不设整行全大写英文或高 letter-spacing。优先 `PingFang SC`（macOS），允许系统字体自然回退。汉字行高为 1.45–1.7；段落间距通过布局控制，不靠硬换行。

## 三、页面文案例子

| 不采用 | 采用 |
|---|---|
| REPOSITORY INTELLIGENCE | 不显示 |
| 用数据，读懂开源项目。 | 分析 GitHub 仓库 |
| 从一个 GitHub 仓库开始，查看活跃度、维护情况与社区协作。搜索、分析、比较，一切都在这里。 | 输入仓库地址，查看项目近期活动与协作数据。 |
| 观察开源生态的变化，从数据里寻找规律。 | 查看研究样本的统计结果与数据质量。 |
| 本研究回答什么问题？ | 统计说明 |
| 管理操作保持简单。 | 管理已添加的仓库，或搜索新的公开项目。 |

## 四、后续实现与验收

- 保持 V4 已有的总览、仓库、详情、比较、研究、任务及设置 Mock 操作可用。
- 界面不要为了“精致感”再补上英文眉题、大段口号、胶囊标签群和装饰性渐变。
- 验收宽度：390px、768px、1280px、1440px；检查单字孤行、按钮基线对齐、列表行高及水平溢出。
- 所有交互组件应具备可见焦点、禁用、加载或结果反馈状态。
- **V4 HTML 是交互演示，不是 Vue 生产代码**。正式实现时应使用设计规则，而非逐字照搬所有 Mock 文案。

# GitHubDA V5 设计系统与组件替换规则

> 目标：**把 V4 的简洁风格变成稳定可复用的 Vue 设计系统**；不允许换组件库后自动变成另一种后台模板。此文档与随包提供的 V4 图像、CSS、原型同时使用。

## A. 视觉定位

- 关键词：简洁 / 克制 / 信息清晰 / 细节精确 / 工具化 / 长时间阅读舒适。
- 默认亮色；深色必须同步处理图表、边框、浮层、焦点和空状态。
- 参考 designeer.xyz 的内容展示秩序、留白和排版观感，但**不得照搬网站首页、品牌口号、英文宣传眉题、夸张几何块**。
- 优先遵守实际中文文案规范：`V4_既有文案排版规范.md`。

## B. 已确认的 V4 原始基础色（从 V4 `styles.css` 提取）

| 用途 | 亮色 | 深色 | 说明 |
|---|---|---|---|
| 应用背景 | `#f7f8f5` | `#121715` | 大面积背景 |
| 内容面板 | `#ffffff` | `#1a201d` | 局部卡片和弹层 |
| 正文字色 | `#1d2623` | `#edf0ea` | 标题、重要数值 |
| 次要文字 | `#77807a` | `#9ca8a0` | 元信息 |
| 更淡文字 | `#9aa19b` | `#7d8b80` | 占位与弱化 |
| 分隔线 | `#e7eae5` | `#303a33` | 细线 |
| 极浅分隔 | `#eff1ed` | `#29332d` | 页眉与容器 |
| 悬浮背景 | `#f1f4ef` | `#252e28` | hover |
| 强调绿 | `#245944` | `#a0d2b0` | 焦点、少量信息强调 |
| 强调弱底 | `#edf4ee` | `#263b2e` | 选中导航 |
| 侧边栏 | `#fbfcfa` | `#171d19` | 与主背景轻微区别 |
| 输入区域 | `#ffffff` | `#1d2420` | 表单 |

> 这是 V4 的 **初始 token**，不是像素级永不可变的约束。可微调对比度与控件状态，但必须全局一致；需做到 WCAG AA 可读性，并在亮/深模式同时验证。

切忌同时保留 shadcn 默认 token 与 V4 token 两套彼此不一致的主题。设计 tokens 必须映射到底层 Button/Input/Popover/Chart 的背景和边框。

## C. 字体和排版

- 系统字体：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`。可以使用系统随附字体，不要打包或传播受版权保护字体文件。
- 普通正文：14px / 行高 1.55–1.65；可读性不足可以提升到 15px。
- 页面标题：24–30px，字重 650–700；总览标题 32–40px 上限；不要为显得设计感而做 60px 中文大字。
- 章节标题：17–19px；仓库标题：14px / 600–660；注释：12–13px（关键状态不要长期小于 12px）。
- 中文字距接近自然排版，不人为设 `letter-spacing: 0.16em`、全部大写英文眉题。
- 中文页面只出现用户需要的文字；不要加“数据洞察、驱动决策、你的个人开源实验室”等装饰性营销词。
- 数字统一使用 `font-variant-numeric: tabular-nums`；大数字应与小数、日期和单位对齐。

## D. 组件规格

| 类型 | 尺寸 / 规则 | 不允许出现的问题 |
|---|---|---|
| 普通按钮 | 高 36–40px，8px 小圆角 | 同一操作组高度不同，文字错位 |
| 紧凑按钮 | 高 32–36px | 一行摆不下就纵向叠三个按钮 |
| 输入与 Select | 高 40–42px，同基线 | 标签与输入字段错位、控件宽度无限伸展 |
| 侧栏条目 | 高 40–44px | 大灰色高亮块、过密或间距太大 |
| 图标 | 16–18px 线性图标 | 同页图标风格混杂、装饰图标过度 |
| 列表项 | 高 72–88px（依描述行数调整） | 每条都变成大卡片、按钮纵排 |
| 页内分隔 | 1px 极淡线 + 适度留白 | 连续多道分隔线、无意义边框嵌套 |
| Dialog | 宽约 440–520px，内容决定高 | 对话框过高、底部控件分散 |
| Toast | 一条简短信息，3–5s（按事件重要性） | 大面积的彩色条、重复提示 |
| 提示状态 | 低强调色 + 文本，必要时图标 | 所有状态都变成亮色 Badge |

- 不要为所有业务容器统一套上 Card 边框；表格与列表优先使用细分隔线。
- Hover 不应造成布局位移；焦点和禁用态必须看得见；点击后能有明确加载与结果反馈。
- 移动端表格可改卡片/横向局部滚动，但不能导致**全页面**横向滚动。

## E. 视觉优先级和截图对照方法

1. 布局骨架：导航 4 项、页首高度、正文左右留白、主要区块结构。
2. 字体：页面标题、仓库名称、说明、数据值的相对比例。
3. 主操作：输入框与“开始分析”在一条基线上。
4. 列表与图表：不因组件库默认样式过度厚重。
5. 细节：色彩、hover/focus、标签、抽屉与弹窗、暗色。

验收不求每个像素相同，但四个一级页面的信息结构、阅读顺序及视觉密度不得明显偏离 V4 原型。

## F. 明确禁止的 AI 模板化设计

- 英文装饰眉题（`REPOSITORY INTELLIGENCE` 等）
- 大段假装产品价值的宣传文案
- 任意英文缩写做大标题
- 一屏十几张圆角卡片与渐变色阴影
- 多色胶囊标签堆积
- 同一信息同时用 Card/Alert/Badge/Toast 提示
- 没有明确语义的插图或伪数据趋势图
- 图表强行填满宽度、n=1 绘制“分布”

## G. 组件采购 / 集成清单

第一批按需添加：Button、Input、Label、Tabs、Checkbox、Select、DropdownMenu、Dialog、AlertDialog、Sheet、Separator、Tooltip、Skeleton、Sonner（或官方当前推荐 Toast 方案）、Progress。后续比较和研究需要时再选 Table / DataTable、Command、Popover。

默认使用 shadcn-vue 暴露的现有组件名称与安装指南，不能照旧版 React shadcn 文档直接拼装 Vue 组件。优先保证键盘可用、焦点返回和 aria-label。

# 页面结构与交互

## 唯一入口和路由

`index.html` 加载 `src/main.ts`，正式路由位于 `src/router/index.ts`，页面、组件与样式统一在 `src/`。

| 路由 | 页面 | 核心能力 |
|---|---|---|
| `/` | 总览 | 真实仓库、活动变化、任务、添加仓库、6 类统计图 |
| `/repositories` | 仓库管理 | GitHub 搜索、加入/移除、筛选、批量删除、进入详情、比较候选 |
| `/repositories/:id/:tab?` | 仓库详情 | 真实路由参数、窗口采集、事件记录、详情抽屉、导出与 ML 分析 |
| `/compare` | 项目比较 | 2–5 候选、共同或独立时间窗口、权重、质量说明、CSV |
| `/research` | 研究图谱 | 300 仓库、筛选、散点框选、列表联动、12 周趋势 |
| `/selection` | 技术选型 | 场景分组、资格筛选、平行坐标、活动轨迹、证据覆盖 |
| `/tasks` | 任务中心 | 真实任务、状态筛选、进度、失败重试与跳转 |
| `/settings` | 设置 | GitHub 深度采集页数读取、校验与保存 |

全局使用单一侧栏和顶栏，主题切换持久化到 `localStorage`。比较页面保留仓库列表与仓库详情中的入口，不出现在侧栏导航。

## 仓库详情页

详情路由支持 `overview`、`activity`、`issues`、`prs`、`releases`、`analysis` 六个 tab。`id` 与 `tab` 均从路由读取，刷新和深链接保持当前仓库与模块。采集窗口为 30/90/180 天；180 天数据不可用时展示原因，不沿用另一窗口的数据。

- **概览**：KPI、Commit/活跃账号/Release 分图、Issue/PR/发布摘要、观察与资料；周数据可打开 Commit 抽屉。
- **开发活动**：作者堆叠周提交、四周均值、作者集中度、UTC 日历热力、分页 Commit 明细。
- **Issue**：周新增/关闭/差值、耗时桶、分页 Issue 记录、详情与 CSV。
- **PR**：周合并量、单条耗时、每周中位数、分时段耗时桶、分页记录、筛选与 CSV。
- **版本发布**：真实日期轴与正式/预发布泳道、相邻发布间隔和发布记录。
- **分析**：本地 ML/维护分析、指标来源、样本和覆盖限制。

图表按真实数据单位分开呈现。原生日期控件负责时间线和 PR 图的时间筛选；日历热力使用 Vue/CSS 网格保留日期单元和部分覆盖状态。未知值、部分样本、完整零值和失败不会混为一类。

## 关键交互

1. 总览接受 `owner/repo` 或 GitHub URL；格式错误显示提示。
2. 仓库列表从 `RepositoryDataSource` 读取，所有增删均调用真实接口；批量删除执行前展示明确确认。
3. 比较由列表勾选 2–5 个仓库后进入 `/compare`，保留时间窗口、权重合法性和导出。
4. 图表 hover 展示来源值、单位、时间窗或覆盖状态；可访问文字列表为 Commit 周和 Issue 周数据提供键盘入口。
5. 点击 Commit 周、Issue/PR 行和 Release 可打开相应明细或抽屉。
6. 加载、空、失败和部分覆盖状态使用当前页面的反馈组件，真实模式错误不回退 Mock。
7. 研究和选型数据保持原有 300 仓库样本用途；不改动 150/150 的模型数据划分。

# 300 仓库数据作为 RepoVantage 默认数据集的适用性分析

- **分析日期：** 2026-11-11
- **分析方式：** 只读检查仓库现有数据、模型评估清单和默认数据包实现；未修改数据、模型或导入逻辑，未发起 GitHub 采集。

## 结论

300 仓库数据**可以成为 RepoVantage 的默认离线课程研究数据集**，但目前不适合直接替换现有 `featured-v1` 包，也不应把对这 300 个样本的所有模型结果都呈现为独立预测。

建议保留现有 15 仓库精选包作为轻量演示集和回退集；将 300 仓库数据转换为单独版本的数据集，仅在课程研究/事实分析场景默认选用。接入时保留每仓库、每模块的覆盖状态和采集时点，并区分模型训练样本与留出样本。

## 现有两类数据

| 项目 | 内置精选集 `featured-v1.0.0` | 300 仓库研究集 `repo-evaluation-2026-v1` |
|---|---|---|
| 仓库数 | 15 | 300 |
| 数据时点 | `2026-10-22T08:32:31Z` | 分析时点 `2026-11-05T10:31:37Z` |
| 时间范围 | 90 天活动窗口、365 天 Release 窗口 | 52 个完整 UTC 周，周统计截止 `2026-11-02T00:00:00Z` |
| 质量状态 | 包内 15 个仓库的 Commit、Issue、PR、Release 覆盖均为 complete | 总体 `partial`；模块状态有部分覆盖/失败，不能整体标为完整 |
| 数据定位 | 人工精选的演示案例，不是 GitHub 总体的概率样本 | 按语言和规模分层的研究样本，也不是 GitHub 总体的概率样本 |
| 当前形式 | RepoVantage 应用的数据包格式 | `MachineLearn` 独立采集库及研究导出格式 |
| 本地体量 | 分发 ZIP 约 3.4 MiB | 采集目录约 536 MiB，其中 SQLite 检查点约 489 MiB |

300 仓库数据较新、覆盖面更广，也包含 15,600 条仓库周统计；此前审查记录其中 15,496 条为完整覆盖、104 条为部分覆盖。部分覆盖、`true_zero`、`not_applicable`、`failed` 必须分别表示，不能把缺失覆盖补成 0。

## 数据质量与解释限制

1. 总体质量报告为 `partial`。300 个仓库的 Profile 均有记录；Commit 为 291 complete、9 true zero；PR 创建为 288 complete、12 true zero；PR 更新有 1 个 `partial_concurrent_change`；Release 有 1 个 `failed`，其余为 complete 或 true zero。
2. 后续 Issue 评论审查发现 62 个仓库共 59,651 条 Issue 的快照 `comments_count` 与响应摘要观察数不一致。现有记录不能区分漏采与后续删除，因此不能将差异直接解释成“14 天内无人回复”。非作者评论也不等于已确认的维护者回复。
3. Profile 是逐仓库采集时的当前快照，不是历史时点 Profile；Commit 是采集时当前默认分支可见记录，不重建历史分支成员关系。
4. 300 仓库是经过筛选和分层的研究样本，不是对 GitHub 全体项目的随机抽样；统计结论只能描述这个样本和明确的观测窗口。
5. 现有 PR 标签样本的目标是“PR 创建后 14 天内是否合并”，不是“仓库是否持续维护”。不能把 PR 标签模型解释为仓库维护预测。

## 与现有模型的关系

课程模型评估使用的源数据正是这 300 个仓库的 52 周周统计，清单标记为 `course_research`，并说明它不是新采集的独立测试集。

| 任务 | 现有评估范围 | 解释边界 |
|---|---|---|
| M1 维护模式聚类 | 210 个训练仓库、45 个验证仓库、45 个测试仓库 | 聚类描述近期 Commit 行为，不代表项目质量或健康度 |
| M2 未来 4 周活动趋势 | 255 个训练仓库、45 个测试仓库 | 若对全部 300 个样本直接展示推断，其中训练仓库的结果属于训练内应用；不得当作独立外推证据 |
| M3 活动异常 | `baseline_only` | 是 MAD 统计规则，不是经标签验证的机器学习异常模型 |

在默认数据中接入 M1/M2 之前，必须能按仓库 ID 识别训练、验证和留出角色。现有公开评估汇总主要记录样本数量；需要确认或导出可追溯的分组清单。无法确认样本角色时，应只显示可核实事实，或明确标注为历史样本演示。

## 当前应用接入差距

- RepoVantage 应用内置 `featured-default` 数据包是 `featured-v1.0.0`，包含 15 个仓库。研究页 `auto` 模式优先选择可分析的正式研究集，否则回退到该精选集。
- 当前 `build_featured_bundle` 明确要求恰好 15 个经人工审核的精选成员；导入器也把包 ID 固定为 `featured-default`。300 仓库采集目录不符合这一应用包格式，不能直接复制或更名后导入。
- 当前应用包由仓库、快照、成员、分析、覆盖、事件和详情等 JSONL 文件组成；课程 ML 周特征存放于独立 CSV/SQLite。现有数据集导入流程没有把该周特征转换为维护分析读取的 `MaintenanceRun` / `MaintenanceWeek` 记录。因此，即使普通仓库事件成功导入，分析独立页也不会自动获得这 300 个仓库的 ML 输入。
- 应用导入器限制 ZIP 为 256 MiB、解压文件总量为 1 GiB、每个 JSONL 文件最多 1,000,000 条记录，并要求文件白名单、校验和与隐私扫描。需要对转换后的目标包实测大小、内存、导入耗时和数据一致性；不能用 536 MiB 采集目录代替产品包。
- `make_server_package.py` 生成的是续采服务器包，明确会包含 `.env` Token 文件；该包不得用于应用分发或默认数据集打包。
- 比较页的候选选择上限为 5 个仓库。将默认数据集扩为 300 不等于支持一次比较全部 300 个仓库。

## 推荐落地方式

1. **保留 15 仓库精选包**：继续作为当前轻量演示和回退，不覆盖 `data/datasets/featured-v1/`。
2. **新增独立版本的数据集标识**：例如 `course-research-300-v1`，在研究界面清楚标为“课程研究样本”，记录来源、数据时点、抽样范围、模块状态与限制；避免把它命名成随机或全覆盖数据集。
3. **只转换应用需要的字段**：生成经过允许列表与脱敏校验的应用包；不放入 SQLite 检查点、续采 `.env`、原始页面日志或非必要正文。周特征需要有独立且可追溯的导入映射。
4. **明确处理覆盖和事实边界**：将部分覆盖显示为部分覆盖，`true_zero` 才表示完整来源下观察为零；分别保留 Profile 快照时间、活动窗口、仓库级模块状态和样本来源。
5. **隔离模型适用范围**：M1/M2 按仓库分组清单标记训练、验证、测试身份；训练样本不展示成独立预测。留出样本也应注明这是同一历史数据集上的回测。M3 始终标记为 MAD 规则。
6. **在隔离数据库验证后再切换研究页默认值**：核对导入前后本地仓库快照不被较旧数据覆盖，逐项检查详情、比较、研究汇总、覆盖状态、任务状态和模型降级。全过程不触发 GitHub 采集。

## 当前判定

| 用途 | 判定 |
|---|---|
| 课程演示中的 300 仓库事实分析 | **适合，需先转换应用数据包并显示覆盖状态** |
| 研究页的默认课程样本 | **有条件适合，需保留独立数据集 ID 和课程样本说明** |
| 直接替换 `featured-v1` 作为所有场景的唯一默认集 | **暂不建议** |
| 对全部 300 个仓库展示独立验证过的 M1/M2 预测 | **不适合；训练样本输出与留出评估必须区分** |
| 把 M3 标为 ML 异常预测 | **不适合；当前是 MAD 规则** |

本分析不授权重新采集、覆盖正式数据库、修改现有精选包或重新训练模型。后续如决定接入，应先完成独立数据包映射与隔离数据库验收，再单独切换默认选择。
